# Galgame 可视化编辑器 · 桌面版使用说明

**构建号：R233 (11-06)**　　版本：0.1.0

## 〇、本版要点（R233 · 模型弹窗位图 + 占位音频静音口径 + 音频格式兼容）

- **R233 · 模型弹窗四页签带目录结构示意图**：🎭 模型弹窗的四个页签（Live2D / Spine / DragonBones / 序列帧）各自加了代表性图标，列表为空与「WebGAL 侧接入说明」里都新增了对应模型的**目录结构内联 SVG 示意图**（.model3.json+.moc3+纹理、.atlas+.json/.skel+.png、*_ske.json+*_tex.json+*_tex.png、GIF/WebM/PNG 序列），一眼看清该把什么文件放进去。
- **R233 · 占位音频静音口径明确**：内置的 BGM / 音效 / 配音占位（无真实音频文件）在编辑器与导出工程里都**保持静音**——播放不出声、不报错、不影响真实音频；导出 WebGAL 时降级为注释，导入带占位的工程不报缺素材。要出声请到素材库导入真实音频替换。
- **R233 · 音频格式兼容更广**：素材导入的音频格式判定从「只认 MIME 前缀」改为「扩展名白名单 + MIME 兜底」，现在 **MP3 / WAV / OGG / M4A / AAC / FLAC / OPUS / WEBM / AIFF** 等都能顺利导入（此前浏览器对 FLAC/AAC/OPUS/AIFF 返回空 MIME 时会被误拒）。实际能否解码仍由浏览器决定（播放 / 波形阶段再兜底）。

### 上一版要点（R232 · WebGAL 场景调用语义显式化）

- **R232 · 导入 WebGAL 时的调用关系看得见了**：官方 `callScene`（调用子场景、播完回到调用点）与 `changeScene`（永久跳转、不返回）此前被同等处理，调用点之后的父章语句还会被误并入子章。现在导入时会把子场景独立成章、把调用点之后的语句单独成「续演」章，并在**归档章节列表**标出「由谁调用 / 是否返回 / 调用时刻」；章节区间仍首尾相接、不重叠。
- **R232 · 语义落差不再隐形**：导入结束会给出一条「调用关系已线性化」提示，应用内使用说明也补了对应章节。此前这里没有任何提示，容易被误认为脚本内容丢失；提示文案明确说明这是结构转换，不是能力缺失。
- **R232 · 导出能回写调用类型**：从官方脚本导入过 `changeScene` 的章节，再导出时该行会写回 `changeScene`；自建工程仍按 `callScene` 链写 `start.txt`，round-trip 产物与之前逐字一致。
- **R232 · 明确不碰的东西**：主时钟 `wgClockInfer`、播放推进 `advanceTo`、存档 / 快进 / 回滚链一律未改，`callScene` 在时钟里仍是并行命令、不推进主时钟。子场景复用与真运行时调用栈仍不在编辑器能力内，手册已写明边界。
- **R233 · 版本口径**：五处构建号统一升到 `R233 (11-06)`（`MS_BUILD_TAG` / 启动 toast / 两份 `tauri.conf.json` 标题；`APP_BUILD` 为日期戳，同日不变），源码快照按新版本号重新生成。

## 〇†、上一版要点（R227 · OffscreenCanvas 演出时钟 + 全轨道可视性审计）

- **R227：演出时钟真正离屏化（OffscreenCanvas）**——此前播放时钟是「主线程累加 rAF 时间差」，窗口最小化/切后台/主线程被长任务卡住时会丢帧、时长漂移。本版起：① 权威时间在 Worker 里用积分式给出（`t = 起点 + 真实流逝 × 速率`，倍速=2、快退=-2），不再逐帧累加；② 帧相位由 Worker 的 16ms 恒定节拍产生，主线程只「消费拍子」，且与 rAF 双挂、谁先到谁推进（可见时 60fps，隐藏时靠拍子，任一路失效都不会卡住播放）；③ 音频试听波形画布通过 `transferControlToOffscreen()` 交给 Worker，波形与播放头完全在 Worker 内绘制——转移后主线程再对该画布取 2D 上下文会抛异常，这正是「确实离屏」的铁证。
- **R227：不支持的环境自动回退**——没有 OffscreenCanvas / transferControlToOffscreen / Worker 的旧内核，自动走原来的 rAF + 心跳路径，网页版与旧系统行为不变；Worker 崩溃或拿不到 2D 上下文时会自动重建画布回主线程绘制，不会出现「波形画死」。
- **R227：全轨道可视性 / 可编辑性审计（12 项全绿）**——针对上一版「轨道不显示 / 双击改不了台词」这一整类缺陷做了全量回归：九条轨道（文案/背景/图片/立绘/背景音乐/特效音乐/配音/特效/故事线说明）逐轨验证——每个片段都能在某个滚动位置被渲染出来（不允许「永久看不见」）、每轨泳道行与标签行都在、预览层真的产出元素、普通台词与分支台词都能双击行内编辑并回车写回、折叠轨确实不渲染且展开恢复、归档视图四章齐全。新增 `r227_audit.cjs`（12/0）、`r227_osclock.cjs`（14/0）、`r227_play.cjs`（6/0）长期看护。

## 〇†、上一版要点（R221 · 导出的游戏 exe 也自动带签名）

- **R221：导出成品游戏 exe 时自动数字签名，用户零操作。** 导出流程末尾（写完自定义图标之后）会自动用同一张发布证书给 `<游戏名>.exe` 再签一次，导出完成提示里显示「（已数字签名）」。
  - **为什么必须"写完图标后再签"**：数字签名是对文件全部字节算的哈希，而「自定义图标」是用 Windows 资源接口改写 exe 里的图标资源＝改字节。先签名后写图标，签名会立刻变成红色「签名损坏」（比不签名更糟）。所以固定顺序：写图标 → 重签。
  - **失败不影响游戏**：签名失败只会降级成「未签名」，游戏照常运行，提示里会写明。
  - **原理**：编辑器内嵌了发布证书，导出时在本机用 PowerShell 的 `Set-AuthenticodeSignature` 完成签名；证书与密钥不联网、不上传。

## 一、运行

1. 关闭已运行的旧版本（若标题栏显示 R200 或更低，先完全退出）。
2. 删除旧的解压目录与旧 zip，重新解压本包。
3. 双击 `galgame-editor.exe`。
4. **核对标题栏**：应显示 `Galgame可视化编辑器 · R233 (11-06)`。若仍是旧构建号，说明解压的还是旧包。

**关于签名与 SmartScreen**

- 本包 exe 使用**自签名证书**（`CN=Galgame Visual Editor`）签名，有效期至 2029-11-02。
  - 在**本机**（证书已装入「当前用户 → 受信任的根证书颁发机构」）：属性里数字签名显示「已验证」，双击无「未知发布者」提示。
  - 在**别的电脑**：双击若弹「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」即可；想让那台电脑也认可，可双击 `证书/galgame-selfsigned.cer` →「安装证书」→ 当前用户 →「将所有的证书都放入下列存储」→「受信任的根证书颁发机构」（详见 `证书/自签名说明.txt`，仅建议在信任的机器上安装）。
- 自签名只能证明「文件自签发后未被改动」，**不具备公共 CA 的全球信任**。要彻底消除陌生电脑的警告，需购买/申请公共 CA 代码签名证书（SignPath 开源项目免费通道 / Certum / Azure Trusted Signing），属后续事项。
- **你自己导出的游戏 exe 同样带这张签名**（R221 起自动完成）：导出完成后右键 `<游戏名>.exe` → 属性 → 数字签名，可看到同一发布者。玩家端要点同上——装了 `证书/galgame-selfsigned.cer` 的机器不再提示。
